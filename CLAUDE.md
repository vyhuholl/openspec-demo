# Сервис бронирования переговорок

HTTP-сервис: создание и просмотр броней переговорных комнат.

## Стек

- Go 1.26+, только stdlib: `net/http`, `encoding/json`, `testing`.
- Хранилище — в памяти. БД, миграций, Docker, авторизации нет.
- Новые зависимости не добавлять. Нужна библиотека — сначала спроси.

## Структура

```
cmd/booking/main.go     — точка входа, роутинг
internal/booking/       — модель, хранилище, логика
acceptance/             — подкладывается снаружи, не читать и не менять
```

## Команды

- `make run` — поднять сервис на :8080
- `make test` — `go test -race ./...`
- `make ai-check` — форматирование, `go vet`, линтер, тесты

`make ai-check` должен проходить перед тем, как считать задачу выполненной. Результат команды заявляется только после реального запуска.

## Соглашения

- Время в API — RFC3339 в UTC.
- Ошибки клиента — 4xx с телом `{"error": "..."}`.
- Тесты table-driven на стандартном `testing`, утверждения через
  `if ... { t.Fatalf(...) }`. testify не вводить.
- Ошибки оборачивать через `fmt.Errorf` с `%w`, паники в хендлерах не допускать.

## Чего не делать

- Не вводить интерфейсы и слои на вырост — один конкретный тип хранилища.
- Не генерировать README, CHANGELOG и комментарии-пересказы кода.
- Не расширять скоуп без явного решения пользователя; идеи «заодно сделать X» отдавать списком.
