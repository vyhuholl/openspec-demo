# Proposal

## Why

В репозитории нет кода сервиса бронирования переговорок — есть только правила проекта и Makefile. Нужен базовый HTTP-сервис: создать бронь комнаты без пересечений и посмотреть брони комнаты за сутки.

## What Changes

- `POST /bookings` — создание брони с валидацией входа (400) и проверкой пересечения с бронями той же комнаты (409).
- `GET /bookings?room=&date=` — брони комнаты, пересекающиеся с сутками `date` по UTC, по возрастанию `start`.
- Все ответы — `Content-Type: application/json`; ошибки (400, 404, 405, 409) — `{"error": "<непустой текст>"}`.
- Хранилище в памяти; проверка пересечения и запись атомарны относительно параллельных запросов.
- Новые файлы: `go.mod` (module `booking`, `go 1.26`), `internal/booking/` (модель, хранилище, HTTP-хендлер, тесты), `cmd/booking/main.go`.

Нефункциональные требования (сценариев в спеке нет, проверка — ручной `make run`):

- порт — из переменной `PORT`, по умолчанию `8080`;
- данные живут в памяти процесса и пропадают при перезапуске.

Вне скоупа (запрос пользователя): отмена и изменение броней, GET по id, авторизация, справочник комнат.

## Capabilities

### New Capabilities

- `bookings`: создание брони переговорной комнаты и выдача броней комнаты за сутки UTC. Требования: формат брони в ответах, создание брони, конфликт броней, выдача по комнате и дате, формат ошибок.

### Modified Capabilities

Нет — архивных спек в `openspec/specs/` нет.

## Решения по вопросам explore

Пользователь принял рекомендованный вариант по каждому вопросу.

| # | Вопрос | Решение |
|---|---|---|
| 1 | `go.mod` отсутствует | module `booking`, директива `go 1.26` (`go mod init` на локальном 1.27 пишет `1.27.0` — править через `go mod edit -go=1.26`) |
| 2 | Дробные секунды в RFC3339 | Принимаются, хранятся без потерь, в ответе отдаются с дробью (`RFC3339Nano`, суффикс `Z`); конфликт считается по точным значениям |
| 3 | Крайние формы RFC3339 | `-00:00` принимается как нулевое смещение; строчные `t`/`z`, пробел вместо `T` — 400 |
| 4 | Регистр ключей JSON | Сопоставление ключей с учётом регистра: `{"ROOM": ...}` — лишнее поле, игнорируется; `room` при этом отсутствует → 400 |
| 5 | GET: `room` из одних пробелов | 400 — то же правило, что в POST |
| 6 | 404/405 | Тоже JSON `{"error": ...}`; у 405 — заголовок `Allow` |
| 7 | Где роутинг | `internal/booking` отдаёт `NewHandler(*Store) http.Handler` (маршрутизация + хендлеры, тестируется через `httptest`); `cmd/booking/main.go` — только `PORT` и запуск сервера |
| 8 | PORT и хранение в памяти в спеке | Нефункциональные, только в proposal, без сценариев |
| 9 | Лимиты размера тела и длины `room` | Не вводятся в этом change — в списке идей |

Подтверждённые пользователем допущения:

- 400 — тело не JSON, включая мусор после объекта (`{...} x`) и пустое тело; `null`, массив или строка вместо объекта; `room`/`start`/`end` неверного типа или `null`.
- «Одни пробелы» — пробельные символы Unicode (как `strings.TrimSpace`): NBSP — пробел, zero-width space — нет.
- `room` сохраняется как пришла, включая пробелы по краям: `" green"`, `"Green"` и `"green"` — три разные комнаты.
- Content-Type запроса не проверяется; лишние query-параметры игнорируются.
- `date=2027-02-30` и `date=2027-11-1` — 400.
- `id` — `crypto/rand.Text()` (26 символов base32, 128 бит случайности); тесты проверяют непустоту и различие id.
- От текущего времени поведение не зависит (бронь в прошлом допустима), поэтому инъекция `now func() time.Time` не нужна.
- Конкурентность проверяется так: N горутин одновременно шлют одинаковый POST в одну комнату → ровно один 201, N−1 ответов 409, GET возвращает одну бронь.

Выведено агентом при написании спеки, подтверждено пользователем после propose:

- `HEAD /bookings` → 405 с `Allow`, как любой метод, кроме GET и POST. Альтернатива — ответ как на GET без тела (так по умолчанию делает `http.ServeMux`).
- Пути, отличающиеся от `/bookings` лишними `/`, `.`, `..` (`//bookings`, `/x/../bookings`), и `/bookings/` → 404 JSON. `http.ServeMux` по умолчанию отвечает на такие пути 307 с `text/html`, что нарушает «все ответы — JSON»; поэтому перенаправлений нет.

## Карта критичности (HIGH)

| Область | Решение | Источник |
|---|---|---|
| 1. Инварианты хранилища | Бронь не пересекается ни с одной бронью той же комнаты. После 400 и 409 в хранилище ровно те же брони, что до запроса | запрос пользователя |
| 2. Атомарность и конкурентность | Операция создаёт не более одной записи — частичного результата нет. Одновременные запросы в одну комнату не создают пересекающихся броней: проверка и вставка под одним захватом блокировки | запрос пользователя |
| 3. Время и календарь | Сутки `date` — `[date 00:00Z; date+1 00:00Z)` по UTC; перевода часов в UTC нет. Допустимые смещения — нулевые (`Z`, `+00:00`, `-00:00`); дробные секунды сохраняются | запрос пользователя; ответы на вопросы 2, 3 |
| 4. Границы | Интервал брони полуоткрытый: касание — не конфликт; `end == start` — 400; бронь, кончающаяся ровно в 00:00, в следующих сутках не видна; начинающаяся ровно в 00:00 следующих суток — не видна в текущих. Сценарии ровно на границе и на секунду/наносекунду за ней | запрос пользователя; ответ на вопрос 2 |
| 5. Объём | Один запрос создаёт не более одной записи — область не затрагивается. Размер тела и длина `room` не ограничены — сознательно, см. список идей | ответ на вопрос 9 |
| 6. Изменение зафиксированного поведения | Не затрагивается: архивных спек нет | — |
| 7. Состояния и переходы | Не затрагивается: у брони нет состояний, отмена и изменение вне скоупа | запрос пользователя |

## Идеи вне скоупа (не реализуются)

- Лимит размера тела (`http.MaxBytesReader`, 413) и лимит длины `room` в рунах.
- Таймауты `http.Server` (`ReadHeaderTimeout` и др.) и graceful shutdown.
- Поддержка `HEAD /bookings`.
- Отклонение JSON с повторяющимися ключами.

## Impact

- Новый код: `go.mod`, `internal/booking/`, `cmd/booking/main.go`. Зависимостей вне stdlib нет.
- Новый HTTP API: `POST /bookings`, `GET /bookings`.
- Makefile, CLAUDE.md и правила проекта не меняются.
